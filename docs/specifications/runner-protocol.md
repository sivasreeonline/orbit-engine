# Runner Protocol

## Purpose
Stable adapter contract between orchestration and independently deployed Go runner. API and assessment logic must not depend on a specific OCI engine or sandbox vendor.

## Execution request
- executionId, attemptId, tenant-safe correlation ID.
- source artifact reference and SHA-256 hash.
- language, runtime version and immutable image digest.
- problem version and authorized test bundle reference.
- action Run/Submit and comparison policy.
- CPU, memory, wall-clock, PID, filesystem and output limits issued by trusted policy service.
- deadline, cancellation token/reference and protocol version.


## Protocol version lifecycle

- Protocol v1 remains a strict legacy parsing contract and is permanently non-executable.
- Protocol v2 is the only contract eligible for future dispatch after producer/consumer parity, authenticated transport, artifact authorization, M0 isolation evidence, and security review pass.
- Never fill missing v1 policy fields at the runner boundary or silently downgrade v2.
- Unknown versions, unknown fields, duplicate keys, case-folding aliases, and trailing JSON values are rejected.

## Execution request v2

The Go model is `protocol.ExecutionRequestV2`. The exact JSON keys are:

- `protocolVersion`: literal `v2`.
- `correlationId`: canonical lowercase UUID generated by the trusted API. It is observability context only, never tenant identity or authorization.
- `executionId`, `attemptId`, `problemVersionId`: opaque control-plane identifiers.
- `action`: `RUN` or `SUBMIT`.
- `language`: `java` or `python`.
- `runtimeVersion`: server-selected pinned language runtime version.
- `runtimeImageDigest`: immutable platform-specific OCI manifest digest in lowercase `sha256:<64 hex>` form. Tags and mutable image references are forbidden.
- `sourceArtifactId` and `sourceSha256`: authorized opaque artifact reference and lowercase SHA-256 digest; source bytes are not embedded.
- `testBundleId`: authorized opaque test bundle reference; hidden inputs and expected outputs are not embedded.
- `comparisonPolicy`: literal `EXACT_BYTES` for M1. Stdout is compared byte-for-byte; no trimming, whitespace folding, Unicode normalization, or line-ending conversion. Stderr is diagnostic only.
- `deadlineAt`: canonical RFC3339 UTC timestamp generated by the trusted control plane. The maximum end-to-end budget is 10 minutes from API intake, including queue wait. Queue wait consumes the budget; expired requests must not start. The runner rejects expired deadlines and deadlines more than 10 minutes in the future. The control plane must preserve the original deadline on retries.
- `cancellationRef`: `cxl_` followed by 32 lowercase hexadecimal characters (128 bits of entropy). This is a lookup reference, not a bearer credential.
- `limits`: server-selected resource policy with the exact fields below.

The `limits` object accepts only:

- `cpuQuotaMillis`, `memoryBytes`, `wallTimeMillis`, `processLimit`, `outputBytes`: positive integers.
- `scratchBytes`: positive integer, at most 536870912 (512 MiB).
- `scratchInodes`: positive integer, at most 8192.

M1 scratch policy defaults are 268435456 bytes (256 MiB) and 4096 inodes per execution. The control plane may assign lower values. The runner rejects values above the hard ceilings. The selected sandbox must enforce both quotas as hard limits on a dedicated writable scratch mount; best-effort monitoring is not sufficient. Immutable runtime and authorized test mounts remain read-only and separately accounted.

The initial runner platform is Linux AMD64. The server resolves the language/runtime/platform tuple to an allowlisted image digest. The runner independently verifies the exact digest, approved Cosign signature identity, and build provenance before sandbox creation. Registry and verification failures are infrastructure failures and fail closed.

Cancellation is accepted only through an authenticated control-plane operation after tenant/attempt ownership checks. The runner must terminate the process tree and sandbox, reap descendants, verify cleanup, and return an authenticated acknowledgement. A cancellation reference alone never authorizes cancellation.

## Strict JSON decoding (request v2)

The v2 decoder uses a separate `ExecutionRequestV2` model and exact key allowlists. It caps the request body at 64 KiB; rejects non-object roots, unknown/non-canonical keys, duplicate keys (including escaped-equivalent keys), nested objects outside `limits`, malformed values, trailing JSON values, unsupported policy values, expired deadlines, and out-of-policy resource limits. The v1 decoder and v1 model remain unchanged.

## Execution result
- executionId and source hash confirmation.
- infrastructureStatus and runnerVersion.
- compilation status and bounded compile output.
- per-test sanitized status, elapsed time and memory measurements.
- exit code, timeout/OOM/output-limit flags.
- bounded stdout/stderr for public tests only.
- startedAt, completedAt and sandbox cleanup status.

## Strict JSON decoding (request v1)

The runner accepts a JSON object with the exact camelCase field names defined by the request model. Field names are case-sensitive; aliases that differ only by casing are not accepted. The decoder rejects duplicate object keys (including keys that become identical after JSON escape decoding), unknown or non-canonical fields, nested objects outside the documented `limits` object, non-object top-level values, trailing JSON values, and request bodies larger than 64 KiB.

The `limits` object accepts only `cpuQuotaMillis`, `memoryBytes`, `wallTimeMillis`, `processLimit`, and `outputBytes`. This strict wire parsing is performed before semantic request validation.

## Protocol requirements
- Authenticate runner service identity; do not trust tenant or resource policy supplied by student.
- Validate all payload fields and artifact hashes.
- Idempotency key is executionId.
- Use explicit deadlines and cancellation.
- Stream or cap output; never buffer unbounded output.
- Distinguish infrastructure failure from student verdict.
- Results must be safe to retry and persist exactly once logically.
- Never return hidden input or expected output.
